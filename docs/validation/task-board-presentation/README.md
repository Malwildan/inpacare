# Task board presentation evidence

These screenshots were generated by `tests/e2e/tugas-board.spec.ts` against a fresh disposable PostgreSQL database and the production web build. All patient, staff, room, and task values are synthetic demo fixtures. The history screenshot deliberately includes null, boolean, long, and unknown nested values to exercise the readable before/after presentation.

- [Board](board-desktop.png): one server total per column, paired Detail/Pindahkan actions for active tasks, and Detail-only terminal cards.
- [Task detail](detail-desktop.png): patient, assignment, schedule, notes, and management sections in the existing shadcn dialog.
- [History on desktop](history-desktop.png) and [at 390 pixels](history-mobile.png): labeled before/after values without a raw JSON block.

The final task-board browser run passed all 16 cases, including native dragging without layout shifts, card-gap and empty-column drops, own-card no-ops, appending past the first loaded page, terminal restrictions, focus restoration, and responsive layouts. Svelte check passed with no warnings or errors; architecture and production build checks passed. The build still reports its existing large-chunk warning. These checks do not establish live deployment behavior.
