## Decision register

Recommendations are proposals to resolve source gaps. The developer owns recording the selected behavior before the dependent implementation is accepted. Unaffected foundation work can proceed while domain decisions remain open.

| ID | Source issue / evidence | Recommended resolution to evaluate | Needed before |

| D-01 — identity and rights | DOC 10630–10633 stores three roles; task flows name a coordinator and PIC; overview uses Admin while billing says Admisi. | Keep base roles DOKTER/PERAWAT/ADMISI; map Admin to Admisi if they are the same actor; store protected coordinator capability for eligible nurses; PIC is task assignment. Specify each action/field/record scope, including delete and reassignment. | M1 authentication/shell policy and M3 task permissions. |
| D-02 — cycle approval | DOC 631–661 requires doctor approval, while 12330–12380 directly applies extend/release. | Use a durable pending-request/decision workflow, preserving the prior effective state until the authorized decision; capture requester, decision actor/time/reason and required notification.
